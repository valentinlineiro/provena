# v0.5.0 — Use it, then interpret it

**Date:** 2026-08-03

## From a capture form to a decision surface

This version turns the web from a place where things are stored into the
place where a career story is visibly maintained and interpreted. Two ideas,
in order, drove the design:

1. **Recordar está resuelto.** The bottleneck is not the model or the
   projections. It is whether the user can keep the story alive with almost
   zero friction, and whether the system then helps them interpret where
   they are.
2. **Narrativa, no dashboard.** Each screen answers one question the user is
   already asking when they open Provena.

## What changed

### Story (Identity Timeline, `/`)

- Observation-first home: identity, current chapter, experiences, milestones,
  capabilities, pending captures, and a contextual "Continue this story".
- English-first UI (language is a projection concern, not data).
- Dogfooding events in KV: `timeline_open`, `capture_created`,
  `capture_curated`, `current_chapter_clicked`.

### Career Compass (`/`, Story section)

- Deterministic engine (no LLM) derived from the profile:
  `positioning`, `readiness`, `strengths`, `gaps`, `nextBestImprovement`,
  `confidence`.
- Narrative render: Assessment → Evidence → Improvement, with a `Why this
  conclusion` detail backed by freshly derived evidence.
- **Insufficient evidence** is distinguished from a negative assessment —
  missing milestones are never interpreted as lack of development.
- `careerHint` is reserved in the model but deliberately not built yet.
- Decision model: constraints are **gates, not scored dimensions** (a 92%
  fit never compensates a hard requirement). Career Fit is deferred until
  decisions on real opportunities are observed.

### Prepare (`/cv`)

- CV preparation as a **web experience** (not CLI) over a decision context:
  `targetRole`, `audience`, `emphasize`, `omit`, experience selection,
  auto-summary.
- Architecture: `Profile` is the single source of truth; Compass and
  CV Projector share **primitives, never results**. The profile never adapts
  or mutates — projections do.
- `cvProjector` pipeline: Profile → experience selection → capability
  emphasis → summary → `ResumeModel` + `ProjectionMetadata` (the web can
  explain what it did).
- Career Snapshot (target role, strongest evidence, highlights), Core
  expertise vs Primary technologies, and CV Readiness hint tied to the
  evidenced gap.

### Navigation & interaction rules (this release's frictions)

- Single persistent nav: `Story | Prepare` (Career reserved, not shown).
- Rule: **the menu changes section; buttons perform actions.** No button
  navigates (the "Prepare CV" CTA and "← Home" link are gone). Only real
  actions remain: Download .md, Open HTML / Print PDF, Continue this story.
- `Preview CV` removed: the preview updates automatically on any context
  change; `Your CV` is a passive heading.
- Navigation shell pulled apart on mobile: brand → links row → content,
  active state as a discreet 1px underline.

## Architectural invariants

- Default CV projection is byte-identical to the prior `resumeProjector`
  output (apart from the additive snapshot).
- Compass and CV Projector interpret the same canonical profile
  independently.
- Profile immutable; only projections adapt.

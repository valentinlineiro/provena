# v0.6.0 — Evaluate, then prepare

**Date:** 2026-08-04

## From a story you maintain to a decision you can justify

This version closes the loop the product has been building toward: not just
recording a career story and projecting it, but looking at a real opportunity
and saying what the evidence actually supports. The interaction unit is the
web — no CLI, no scraping, no application automation.

Two ideas drove the design:

1. **Deterministic honesty.** Provena answers "should I apply?" using only
   what it already knows, with every reason traced to the canonical profile.
   No LLM, no API keys, no external infrastructure.
2. **Distinguish "I don't understand" from "you have no evidence."** Absence
   of recognition is never treated as absence of evidence.

Underneath the new surface, the release also completes the move to a single
canonical profile and a contribution-driven projection pipeline.

## What changed

### Opportunity Evaluation (`/evaluate`)

- Paste a job description → APPLY / CONSIDER / SKIP. Always a three-way
  verdict, never a fabricated recommendation.
- Deterministic signal matching: each capability carries a `signals`
  vocabulary; the JD is scanned for phrases Provena can honestly evaluate.
- Results: **criteria** (compensation, work mode, roles, avoid — each
  satisfied / violated / unknown), **demonstrated** (matched capability +
  the JD phrases + your recorded evidence), **gaps** (recognized but no
  recorded evidence), **notEvaluated** (unrecognized parts), and
  coverage / interpretation coverage / confidence per offer.
- Handoff: APPLY → "Prepare application" → `/cv?role=…&emphasize=…` pre-fills
  the CV page from the evaluation's `decisionContext`; `/api/cv/preview`
  consumes the pre-filled context.

### Canonical profile (`profiles/valentin`)

- Single source of truth, replacing the example workspaces; web bundle is
  regenerated from it, tests use synthetic workspace helpers.
- All Summa Networks facts migrated losslessly into `contributions` with
  `capabilityIds`, so evaluation and projection read real evidence instead
  of gaps; contributions count as experience milestones in the timeline.
- Explicit vocabulary authority: the projector no longer injects implicit
  leadership vocabulary into claims.

### Contribution-driven projection (R2/R4b/R5/R6)

- Renderer-neutral CV projection with evidence ranking and sentence-level
  dedup; target relevance reorders selection, never evidence truth.
- Contribution entities with Scope/Outcome; contribution-level semantic
  evaluation and lexicographical Scope ranking in the selection pipeline;
  contribution-aware evidence budget and project selection.

### Landing projections

- Declarative landing projections: capability types, evidence resolvers,
  `LandingPolicy` and a pure `landingProjector`, with
  `provena landing review` / `provena landing accept` CLI commands.

## Invariants

- **I-OE-1:** absence of recognition ≠ absence of evidence — unrecognized
  JD text is `notEvaluated`, never a gap.
- **I-OE-2:** every claim traces to a canonical capability and its recorded
  evidence.
- **I-OE-3:** a violated criterion requires positive evidence — extraction
  failure yields `unknown`, never `violated`.

## Fixes in this release

- Salary extraction no longer truncates at trailing punctuation
  (`€100,000 - €120,000.` parses correctly instead of reading €120).
- Contributions now count as experience milestones in the career timeline
  (the canonical profile migration moved Summa's 5 achievements to
  contributions, which the timeline previously ignored).
- CV page escapes URL-derived `emphasize` values before inserting into the
  DOM (no HTML injection from a crafted `/cv` link).

# Release Retrospective — v0.7.0

**Release Date:** 2026-08-07  
**Software Version:** v0.7.0  
**Governance Record:** [ADR-001](../architecture/adr/ADR-001-v0.7.0-architectural-reconciliation.md)

---

## 1. What Went Well

- **Architectural Reconciliation**: Successfully reconciled software code, documentation, product roadmap, versioning hierarchy, and research programs under explicit governance (ADR-001).
- **Single Source of Truth**: Monorepo package versions synchronized to `0.7.0` across all packages, establishing a single reference version while decoupling research/protocol versions.
- **Neon-First Canonical Market Store**: Replaced KV blob storage with Neon PostgreSQL as the single canonical store for market postings, eliminating numeric `OFFSET` performance bottlenecks and heavy prose duplication in Cloudflare KV.
- **Non-Destructive Posting Lifecycle**: Implemented deterministic status transitions (`ACTIVE` → `NOT_SEEN` → `INACTIVE` → `ARCHIVED`) without `DELETE` statements, keeping complete operational market history.
- **Immutable Relational Assessment Events**: Transitioned from mutating single assessment state to storing immutable assessment evaluation events (`opportunity_assessments`, `assessment_evidences`) and serving current state via `current_opportunity_assessments` SQL view.
- **Keyset Reading Bookmarks**: Implemented Base64URL-encoded versioned keyset pagination (`nextBookmark` tuple: `tier, priority_score, confidence, last_seen_at, opportunity_id`), replacing unstable numeric cursors.
- **Graceful Fallbacks**: Confirmed that the application operates cleanly in both local developer mode (KV/in-memory) and production cloud mode (Neon PostgreSQL + Cloudflare Cron).
- **Clean Documentation Hierarchy**: Established [`docs/project-status.md`](../project-status.md) and [`docs/architecture/freeze-v0.7.0.md`](../architecture/freeze-v0.7.0.md) so any developer can inspect live subsystem status and architectural boundaries immediately.

---

## 2. Technical & Architectural Debt Remaining

- **Database Connection Pooling**: While Neon PostgreSQL integration is operational via `@provena/market-postgres`, connection pooling under heavy concurrent Worker requests can be further optimized.
- **K12 Research Isolation**: K12 knowledge acquisition scripts currently live in `experiments/k12-learning/`. As research matures toward promotion, formal CLI tooling for pattern inspection should be introduced.
- **Local Dev Server Launcher**: A single root CLI command (`npm run dev:all`) to launch both local PostgreSQL mocks and Wrangler dev servers simultaneously would improve developer experience.

---

## 3. Next Operational Frontier

With `v0.7.0` establishing a solid architectural foundation (O2 Shared Market + Attention Inbox powered by Neon canonical store and keyset bookmarks), the next operational focus will be:

1. **Attention Validation (Phase 5)**: Empirically measuring user observation time reduction when processing incoming market opportunities.
2. **Knowledge Promotion Pathway**: Defining formal criteria for promoting experimental K12 pattern definitions into production Operational Knowledge Version `1`.
